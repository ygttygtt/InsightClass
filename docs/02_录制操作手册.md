# RTSP 摄像头录制操作手册

> 使用 `scripts/record_multi_rtsp.py` 并行录制摄像头视频，用于创建训练数据。
> 项目不再内置任何内部地址或密码。

## 1. 前置条件

- Python 3.10+
- OpenCV 已安装
- 电脑能访问摄像头网络
- 已获得数据采集、人员告知和保存期限方面的授权

```powershell
python -c "import cv2; print(cv2.__version__)"
python scripts/record_multi_rtsp.py --help
```

示例使用 RFC 5737 文档地址 `192.0.2.x`，请替换成实际摄像头 IP。

## 2. 安全配置凭据

推荐只在当前 PowerShell 会话设置环境变量：

```powershell
$env:INSIGHTCLASS_RTSP_USERNAME = "admin"
$env:INSIGHTCLASS_RTSP_PASSWORD = "your-password"
$env:INSIGHTCLASS_RTSP_PORT = "554"
```

脚本不会打印包含凭据的完整 RTSP URL。未设置密码环境变量时会在启动时安全提示
输入。虽然支持 `--password`，但它可能进入命令历史或进程列表，不建议在共享机器
上使用。

使用完毕可清除当前会话变量：

```powershell
Remove-Item Env:INSIGHTCLASS_RTSP_PASSWORD -ErrorAction SilentlyContinue
```

## 3. 连接诊断

先用单路工具测试主/子码流：

```powershell
python scripts/rtsp_preview.py 192.0.2.10

# 指定非默认端口，或优先预览子码流
python scripts/rtsp_preview.py 192.0.2.10 --port 8554 --sub
```

工具会分别读取 Channel 101 和 102 的前 10 帧，报告分辨率、FPS、读取失败和黑帧
情况，然后选择可用码流打开预览。按 `Q` 退出。

## 4. 多路录制

### 基础录制

```powershell
python scripts/record_multi_rtsp.py --ips 192.0.2.10 192.0.2.11
```

默认行为：

- 使用 Channel 101 主码流
- 通过 TCP 传输 RTSP
- 输出约 15 FPS、宽度 960 的 MP4
- 优先使用 H.264 编码器，不可用时回退 `mp4v`
- 写入 `data/raw_videos/manual/`

### 输出分类

`--view` 只决定目录名称，不再自动填充摄像头：

```powershell
python scripts/record_multi_rtsp.py `
  --view front `
  --ips 192.0.2.10 192.0.2.11

python scripts/record_multi_rtsp.py `
  --view rear `
  --ips 192.0.2.20 192.0.2.21
```

输出分别位于 `data/raw_videos/front/` 和 `data/raw_videos/rear/`。也可通过
`--output D:\recordings\class-a` 指定目录。

### 子码流与预览

```powershell
# 使用 Channel 102/H.264，通常兼容性更好
python scripts/record_multi_rtsp.py --ips 192.0.2.10 --sub

# 打开预览；预览模式默认使用子码流
python scripts/record_multi_rtsp.py --ips 192.0.2.10 --preview

# 子码流录制，同时另连主码流用于高清预览
python scripts/record_multi_rtsp.py `
  --ips 192.0.2.10 `
  --sub `
  --preview `
  --preview-main
```

`--preview-main` 会为每台设备建立第二路 RTSP 连接，可能超过摄像头并发连接限制。

## 5. 停止与输出

- 无预览时按 `Ctrl+C`。
- 有预览时按 `Q` 或 `Ctrl+C`。
- 脚本会等待录制线程释放 `VideoCapture` 和 `VideoWriter`。

文件名格式：

```text
<camera-ip>_<YYYYMMDD_HHMMSS>.mp4
```

录制结束后应抽查画面、时长、FPS、音视频需求和文件是否可解码，再进入抽帧流程。

## 6. 常见问题

### 连接失败

1. 确认 IP、端口和网络路由。
2. 确认摄像头已开启 RTSP 服务。
3. 检查账号权限和密码，不要把凭据贴到 Issue。
4. 用厂商客户端或 VLC 交叉验证。

### 主码流黑屏

主码流可能是本机 OpenCV 无法解码的 H.265。先运行诊断工具，再增加 `--sub` 使用
Channel 102/H.264。

### 多路录制卡顿

- 减少同一电脑并行摄像头数。
- 使用子码流。
- 关闭预览或 `--preview-main`。
- 将输出写入速度稳定的本地磁盘。

### 输出文件无法播放

检查日志是否从 `avc1` 回退到 `mp4v`。录制进程被强制结束可能导致容器未正确
收尾，应使用 `Q` 或 `Ctrl+C` 正常停止。

## 7. 数据治理

原始课堂视频不进入 Git，也不应附加到公开 Issue/Release。采集前应定义访问人员、
用途、存放位置、加密措施和删除日期。用于模型训练时，优先裁剪或脱敏与任务无关
的身份信息。
