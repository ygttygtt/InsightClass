# 模型实验手册

> 目标是让每次模型结论可复现、可比较，并能明确追溯到数据和配置版本。

## 1. 实验命名

推荐格式：

```text
{stage}_{backend}_{weights}_{dataVersion}_{imgsz}_{epochs}_{tag}
```

示例：

```text
baseline_ultralytics_yolo11n_v2_960_e80
compare_ultralytics_yolo26n_v2_960_e80_augv2
```

名称只写关键变量，完整参数由配置和实验记录保存。不要复用已有 `run_name` 覆盖
旧结果。

## 2. 实验前冻结项

同一比较组必须固定：

- 数据集版本、Manifest 和类别顺序
- train/val/test 的视频级划分
- 评估集、指标口径和随机种子
- 软件版本、GPU/CUDA 环境和预处理方式
- 决策阈值或阈值搜索方式

允许变化的实验变量包括模型、输入尺寸、批大小、训练轮数、增强和优化器。一次
只改变 1 至 2 个关键变量，否则无法归因。

## 3. 基线配置

仓库提供：

- `configs/training_v2_ultralytics.yaml`：YOLO11n
- `configs/training_v2_ultralytics_yolo26n.yaml`：YOLO26n
- `configs/training.ultralytics.example.yaml`：通用模板

配置中的权重路径位于 `models/`，数据集 YAML 默认位于
`data/processed/classroom_behavior_v2/dataset.yaml`。复制配置后再修改，不要把本地
绝对路径写回公共模板。

## 4. 建议实验序列

1. 使用小模型和固定数据打通完整训练/验证/推理链路。
2. 固定输入尺寸和轮数，对比不同模型规模。
3. 固定模型，对比 `imgsz` 对后排小目标的影响。
4. 根据错误分析调整增强或数据采样，而不是只增加 epochs。
5. 冻结候选模型，在独立 test 集和实际视频上做最终评估。
6. 导出 ONNX，验证发行环境中的数值和速度差异。

## 5. 必须记录的结果

- 实验 ID、开始时间、代码提交 SHA
- 数据版本、类别表和 Manifest 摘要
- 模型初始权重及校验值
- 全部训练参数和运行环境
- mAP50、mAP50-95、precision、recall
- `phone_use`、`talking`、`sleeping`、`standing` 的分类别指标
- 混淆矩阵、训练曲线、失败日志和推理速度
- 典型误检/漏检、难例和主观视频观察
- 是否进入下一轮及依据

总 mAP 不能替代分类别分析。低频类、后排小目标和相似行为必须单独检查。

## 6. 运行与汇总

```bash
insightclass train --config configs/training_v2_ultralytics.yaml
insightclass validate --config configs/training_v2_ultralytics.yaml

insightclass compare-experiments \
  --experiments-root experiments \
  --output reports/experiment_summary.csv
```

训练产物默认位于 `experiments/<run_name>/`。不要提交大型权重和实验目录；正式
候选模型应复制到受控模型仓库，并记录来源实验与校验值。

## 7. 进入下一轮的条件

候选模型至少应满足：

- 关键类别指标相对基线有可解释提升
- 独立 test 集没有明显退化
- 实际课堂视频的误检/漏检得到人工复核
- ONNX 导出成功且发行环境推理结果可接受
- CPU 延迟、内存和包体满足部署约束

某一项显著退化时，应保留失败实验记录并说明原因，不能只删除产物。

## 8. ONNX 发布验证

可使用 Ultralytics 导出候选模型：

```bash
yolo export model=experiments/<run_name>/weights/best.pt format=onnx imgsz=960
```

将确认过的 ONNX 放入 `models/onnx/` 前，应完成：

1. 随机样本上的 PT/ONNX 检测框、类别和置信度对比。
2. Windows CPU 环境的启动、首帧和持续推理延迟测试。
3. 四类行为与空白负样本的冒烟验证。
4. 文件来源、opset、输入尺寸和 SHA-256 记录。

模型替换属于功能变更，必须重新构建并验证 Release，不能只覆盖附件中的文件。
