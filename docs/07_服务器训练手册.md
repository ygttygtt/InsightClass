# GPU 服务器训练手册

> 面向 Linux GPU 服务器。示例使用占位路径和主机名，不包含固定账号或组织内部
> 环境信息。

## 1. 环境要求

- Linux 与 Bash
- Python 3.10+
- 与 PyTorch 兼容的 NVIDIA 驱动/CUDA
- 足够保存数据集、环境和实验产物的磁盘空间
- 对项目仓库和数据存储的合法访问权限

先检查：

```bash
python3 --version
nvidia-smi
df -h
```

## 2. 准备代码与数据

在服务器选择工作目录：

```bash
git clone https://github.com/ygttygtt/InsightClass.git
cd InsightClass
git switch main
git pull --ff-only
```

训练数据不进入 Git。将 `classroom_behavior_v2` 安全传输到：

```text
data/processed/classroom_behavior_v2/
|-- images/{train,val,test}/
|-- labels/{train,val,test}/
`-- manifest.yaml
```

例如从本地上传压缩包：

```bash
scp classroom_behavior_v2.tar.gz <user>@<server>:/srv/insightclass-data/
```

在服务器解压时确认目标路径，避免覆盖其他数据。数据含个人信息时应使用受控存储
和加密传输，不要通过公开网盘、Issue 或 Release 分发。

## 3. 初始化环境

仓库脚本会创建 `.venv`、安装 `.[ultralytics,dev]`，并在 V2 数据目录存在时生成
数据集 YAML 和质检报告：

```bash
bash -n scripts/server_setup.sh scripts/server_train.sh
bash scripts/server_setup.sh
source .venv/bin/activate
```

检查输出中的 PyTorch、CUDA 和 Ultralytics 版本：

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
python scripts/test_environment.py
```

`scripts/server_setup.sh` 当前约定数据集目录为
`data/processed/classroom_behavior_v2`。使用其他版本时，手工生成 YAML 并复制训练
配置，不要修改公共模板为个人绝对路径。

## 4. 启动训练

脚本支持仓库内的两份 V2 配置：

```bash
# 前台训练
bash scripts/server_train.sh yolo11n
bash scripts/server_train.sh yolo26n

# nohup 后台训练
bash scripts/server_train.sh yolo11n bg
```

脚本会验证 `models/yolo11n.pt` 或 `models/yolo26n.pt` 是否存在，并显示选择的配置、
实验名和首块 GPU。后台模式会输出日志文件和 PID。

```bash
tail -f train_yolo11n_<timestamp>.log
watch -n 1 nvidia-smi
kill <pid>
```

停止前确认 PID 属于当前训练进程。`kill` 是正常终止请求；不要对不明 PID 使用
强制信号。

也可直接运行自定义配置：

```bash
source .venv/bin/activate
insightclass train --config configs/my_training.yaml
```

## 5. 多 GPU 与资源调整

在复制的训练配置中设置设备，例如：

```yaml
device: "0,1"
batch_size: 16
workers: 4
```

先用小批量冒烟训练确认数据和分布式环境，再逐步增加 batch/workers。OOM 时按以下
顺序调整：

1. 降低 `batch_size`。
2. 降低 `image_size`。
3. 减少缓存和 workers。
4. 使用更小模型。

不要根据 GPU 型号直接照抄批大小；显存还会受驱动、模型和增强方式影响。

## 6. 结果验证

训练完成后检查：

```bash
ls -lah experiments/<run_name>/
ls -lah experiments/<run_name>/weights/

insightclass compare-experiments \
  --experiments-root experiments \
  --output reports/experiment_summary.csv
```

至少保留 `best.pt`、配置、metrics、结果图、混淆矩阵、代码 SHA 和日志。下载模型
前生成校验值：

```bash
sha256sum experiments/<run_name>/weights/best.pt
scp <user>@<server>:/path/to/InsightClass/experiments/<run_name>/weights/best.pt .
```

本地再次计算 SHA-256，确认传输一致。

## 7. 中断与恢复

后台脚本不会自动承诺恢复中断训练。Ultralytics 的恢复方式取决于版本和产物，先
确认 `last.pt` 完整，再按官方参数显式恢复。不要直接重跑相同 `run_name` 覆盖旧
目录；先备份日志和最后权重。

## 8. 故障排查

| 问题 | 检查 |
|---|---|
| `CUDA out of memory` | 降低 batch/imgsz，确认没有残留训练进程 |
| 找不到 `dataset.yaml` | 重新运行 setup，或手工执行 `write-yolo-yaml` |
| 找不到模型权重 | 确认文件位于 `models/` 且 Git LFS/下载完整 |
| CUDA 不可用 | 核对驱动、PyTorch 构建和虚拟环境 |
| SSH 断开训练停止 | 使用 `bg`、tmux 或受管作业系统 |
| 指标异常升高 | 检查视频级数据泄漏和类别顺序 |
| Shell 出现 `\r` 错误 | 确认脚本保持 LF；仓库 `.gitattributes` 已强制该规则 |

## 9. 训练后的发布路径

训练权重不能直接替换 Release。应按 [实验手册](06_实验手册.md) 完成 test 集和
ONNX 对比，再更新 `models/onnx/`、版本、更新日志，最后执行
[打包与发行](09_打包与发行.md) 的全套验证。
