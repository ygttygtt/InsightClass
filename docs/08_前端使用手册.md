# Web 与桌面前端使用手册

> 适用于 InsightClass `1.2.x`。桌面版和浏览器版使用同一套 React 界面。

## 1. 启动

### Windows 便携版

完整解压 `InsightClass-Web.zip`，双击 `InsightClass.exe`。窗口先显示启动页，后端
就绪后自动进入应用。模型仍在后台加载时，控制台会显示“模型加载中”。

可以右键 `InsightClass.exe` 选择“发送到 -> 桌面快捷方式”。快捷方式应指向解压
目录中的 EXE；不要把 EXE 单独复制到桌面，因为 `_internal/` 保存前端、推理引擎
和模型等必需资源。

### 源码 Web 服务

```powershell
python -m pip install -e ".[web]"
Push-Location frontend
npm ci
npm run build
Pop-Location
insightclass serve --host 127.0.0.1 --port 8000
```

访问 `http://127.0.0.1:8000`。局域网访问可绑定 `0.0.0.0`，但应增加网络访问
控制；浏览器摄像头在非 localhost 页面通常需要 `--https`。

## 2. 界面结构

- 左侧：五种检测源、上传队列、模型、置信度和 IoU。
- 中间：实时画面/媒体播放器、检测框、状态提示和统计。
- 右侧：摄像头列表、连通状态和摄像头管理。
- 顶部：设置、监控大屏、开始和停止。
- 左上角太阳/月亮按钮：切换浅色/深色主题。

第一次打开时主题跟随系统偏好，手动选择后保存在浏览器本地存储。桌面版使用
`configs/webview/` 保存 WebView 偏好和缓存，重启应用后仍会保持。监控大屏在新
窗口打开时读取同一偏好，图表文字、网格和背景会同步变化。

检测框会根据媒体原始尺寸和 `object-fit: contain` 后的实际显示区域换算，不会因
窗口比例或黑边直接拉伸。视频框按播放器当前帧选择，不按分析请求返回顺序显示。

## 3. 模型与参数

模型列表优先来自 `experiments/` 中的有效实验；没有实验记录时会发现 `models/`
中的模型。桌面发行版默认使用内置 ONNX 模型，开发环境也可以选择实验中的 `.pt`
模型。

- 星标按钮：将当前模型保存为下次启动的默认模型。
- 置信度：过滤低置信检测，范围 `0.05..0.95`。
- IoU：控制同类重叠框 NMS，范围 `0.10..0.90`。

服务启动时优先校验并预加载已保存默认模型；路径失效则回退到可用内置模型。加载
失败会在页面显示错误，不会把空白界面伪装成可用状态。

## 4. RTSP 监控

### 首次配置

1. 打开“设置”。
2. 填写共享 RTSP 用户名、密码和端口。
3. 保存摄像头设置。
4. 在右侧添加摄像头 IP、名称和备注，或导入 CSV。

应用不内置密码。设置页面读取时只显示“已配置”和尾部掩码；密码框留空保存会
保留原密码。

### 监看和检测

1. 选择摄像头后，应用连接 MJPEG 监看流。
2. 等待状态从“连接中”变为在线。
3. 点击“开始”，每秒取最新帧执行一次检测。
4. 点击“停止”会停止检测并释放该摄像头的服务端流。

每个摄像头拥有独立连接。主码流持续黑帧时服务端尝试 Channel 102；读取失败会
重试，失败原因会显示在画面区域。

### 摄像头管理

- 新增/编辑：IP 必须是合法 IPv4，凭据使用全局设置。
- 删除：只允许删除用户配置的摄像头。
- 连通测试：检查 RTSP 端口和读取帧能力，不代表模型推理一定成功。
- CSV 导入：最大 5 MiB，支持 UTF-8/GBK/GB18030 等常见编码；密码列会被忽略。

## 5. 电脑摄像头

1. 选择“电脑摄像头”。
2. 点击“开始”并授权摄像头权限。
3. 浏览器将帧压缩为 JPEG，约每秒调用一次单帧检测。
4. 点击停止或切换检测源时，所有 `MediaStreamTrack` 会停止并释放设备。

WebView 或浏览器不支持媒体接口、权限被拒绝、设备被占用时，页面会显示具体错误。

## 6. 图片检测

可拖放或选择多个文件，并在文件面板切换。后端支持 JPG、JPEG、PNG、BMP、WebP：

- 单文件最大 25 MiB
- 解码后最大 5000 万像素
- 结果包含标注图、检测框和推理延迟

扩展名正确但无法解码的文件仍会被拒绝。

## 7. 视频检测

支持 MP4、AVI、MOV、MKV、M4V、WebM，单文件最大 2 GiB。

1. 选择视频后可先在本地播放器预览。
2. 开始分析，服务端逐帧返回 `frame_index` 和检测框。
3. 分析完成后播放原视频；暂停、继续或拖动进度条时检测框会跟随当前帧。

视频越长、输入越大，处理时间越长。桌面发行版使用 CPU ONNX Runtime，不能以
浏览器播放速度推断分析速度。

## 8. 批量检测

批量模式最多 20 个视频，总大小不超过 8 GiB，单文件仍不超过 2 GiB。

1. 将多个视频加入队列。
2. 点击“开始批量检测”。同一批次只能启动一次。
3. 页面轮询每个文件的 pending/processing/done/error 状态。
4. 完成后可查看单项回放并导出 CSV 或 JSON。

服务端顺序处理批次，完成或失败约 1 小时后清理内存记录和临时文件。应用退出时
也会清理未完成任务。

## 9. 监控大屏

“大屏”展示：

- 摄像头总数、在线数和四类行为累计计数
- 行为分布、摄像头堆叠对比和 24 小时趋势
- 每台摄像头状态、分类统计和最后更新时间
- CSV 报告导出

趋势和统计来自当前后端进程的真实内存记录，不是模拟数据；后端重启后会重置。
只有 RTSP 检测结果会计入摄像头 Dashboard。

### AI 分析

先在设置中配置 OpenAI 兼容服务并测试连接，再在大屏点击“AI 分析”。服务端只将
聚合统计和趋势 JSON 发给模型，要求其指出风险、优先摄像头和可执行建议。原始
视频帧不会通过该功能发送给大模型。

## 10. 设置

设置窗口包括：

- RTSP 用户名、密码和端口
- OpenAI 兼容 Base URL、模型、API Key 和超时（1..300 秒）
- 大模型连接测试
- 摄像头 CSV 导入

Base URL 可以填写服务根 `/v1` 或完整 `/chat/completions`，服务端会规范化。URL
不能内嵌用户名或密码。环境变量 `OPENAI_BASE_URL`、`OPENAI_MODEL`、
`OPENAI_API_KEY` 的优先级高于本地文件。

## 11. 桌面生命周期

- 关闭窗口：隐藏到系统托盘，后端继续运行。
- 双击托盘图标/“打开 InsightClass”：恢复窗口。
- 再次运行 EXE：唤醒已有实例，不启动第二个后端。
- 托盘“退出”：停止后端、摄像头、批任务和托盘进程。

EXE、任务栏、标题栏和托盘均使用同一品牌图标。启动时出现的加载页并不代表另一个
程序；后端就绪后该窗口会直接切换到主界面。

桌面端优先使用 8000，冲突时选择其他本地端口并写入 `configs/.port`；单实例控制
端口写入 `configs/.control`，正常退出会清理。

## 12. 故障排查

### 页面打不开或桌面窗口空白

源码模式确认前端已执行 `npm run build`。桌面版确认 `_internal/` 与 EXE 在同一
目录，并安装 Microsoft Edge WebView2 Runtime。

### 主题没有保留

确认应用目录可写，且安全软件没有阻止 `configs/webview/`。删除该目录可重置桌面
WebView 缓存和主题偏好；不会删除摄像头、大模型设置或实验。

### 一直显示模型加载或模型失败

检查 `/api/system/status`、模型文件是否完整，以及默认模型是否位于允许的
`models/` 或 `experiments/` 目录。保存一个可用模型后重启验证。

### RTSP 连接失败/黑屏

确认网络、IPv4、端口和凭据；使用 `scripts/rtsp_preview.py` 诊断 101/102 码流。
不要在日志或 Issue 中提交完整 RTSP URL。

### 电脑摄像头无法启动

检查系统隐私权限、是否被其他程序占用，以及页面是否为 localhost/HTTPS。停止后
仍被占用时刷新页面或从托盘退出应用。

### AI 分析失败

先使用“测试连接”，确认 Base URL、模型名、API Key、网络和服务是否实现 OpenAI
Chat Completions 响应格式。视觉检测不依赖大模型，分析失败不会阻止检测。
