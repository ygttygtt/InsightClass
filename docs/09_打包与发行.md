# Windows 打包与 GitHub Release

> 适用于 InsightClass `1.2.x`。发布顺序必须是：检查 -> 提交 -> 构建 -> 冒烟 ->
> 标签/Release -> 远端核验。

## 1. 发行形态

Windows 便携版包含：

- React 生产前端
- FastAPI/uvicorn 本地后端
- ONNX Runtime、OpenCV 和内置 ONNX 模型
- pywebview 独立窗口与 pystray 系统托盘
- 正式 ICO、托盘 PNG、Windows 文件版本和深浅主题前端

输出：

```text
dist/InsightClass-Web/                 可直接运行的完整目录
dist/InsightClass-Web/InsightClass.exe 无控制台窗口入口
InsightClass-Web.zip                   GitHub Release 附件
```

当前不生成安装程序。ZIP 必须完整解压，不能只分发 EXE。用户可为解压目录中的
EXE 创建桌面快捷方式。PyInstaller 使用 onedir，不使用 onefile，因此每次启动不
需要先把依赖释放到临时目录。

## 2. 构建与运行要求

构建机：

- Windows 10/11
- Python 3.10+
- Node.js LTS 与 npm
- PowerShell 5.1+ 或 PowerShell 7
- 可访问 Python/npm 包源

目标机器不需要 Python/Node.js，但需要 Microsoft Edge WebView2 Runtime。正式发行
建议使用代码签名证书；未签名 PyInstaller 程序可能触发启发式检测。

## 3. 发布前版本检查

Python、前端、标签和目标 Release 必须一致：

```powershell
Select-String -Path pyproject.toml -Pattern '^version'
python -c "import insightclass; print(insightclass.__version__)"
node -p "require('./frontend/package.json').version"
python -m pytest tests/test_version.py -q
git tag --list "v1.2.0"
gh release view v1.2.0 --repo ygttygtt/InsightClass
```

新版本发布前更新 `CHANGELOG.md`。已有同名正式 Release 时不要覆盖附件或移动标签，
应增加补丁版本。

## 4. 工作区与敏感信息检查

```powershell
git status --short --branch
git diff --check

rg -n "password\s*=|api[_-]?key\s*=|rtsp://[^ ]+@" `
  src scripts configs docs README.md `
  -g '!configs/app.yaml' `
  -g '!configs/cameras.yaml'
```

确认：

- `main` 已同步到 `origin-github/main`
- 没有未提交的功能/文档变更
- 没有真实 RTSP 密码、API Key、内部 IP、课堂视频或数据集
- `configs/app.yaml` 和 `configs/cameras.yaml` 没有被跟踪
- `build/`、`dist/`、`experiments/` 和 ZIP 没有进入提交

历史中已出现过的密钥应立即轮换；只删除当前文件不能让旧密钥重新安全。

## 5. 质量门槛

```powershell
python -m pytest -q
ruff check src scripts tests

Push-Location frontend
npm ci --no-audit --no-fund
npm audit --omit=dev --audit-level=high
npm run build
Pop-Location

bash -n scripts/server_setup.sh scripts/server_train.sh
```

任何一步失败都停止发布。不能用“文档改动”或“本机能启动”跳过自动化检查。

## 6. 构建便携版

```powershell
# 安装 .[web] 和 PyInstaller 后构建
.\scripts\build_package.ps1

# 当前环境依赖已经验证时
.\scripts\build_package.ps1 -SkipDeps

# 指定解释器
.\scripts\build_package.ps1 -Python "C:\path\to\python.exe"
```

脚本执行：

1. 验证 spec、品牌/版本资源、类别表、ONNX 模型和前端锁文件。
2. 使用 `npm ci`/`npm run build` 生成前端。
3. 使用 `InsightClass.spec` 创建 `console=False` onedir 应用。
4. 复制干净的 README/LICENSE，创建空运行时配置和实验目录。
5. 生成 `InsightClass-Web.zip`。

脚本会重建 `dist/InsightClass-Web/`，不要把用户唯一数据放在该目录。

## 7. 产物检查

```powershell
$packageDir = Resolve-Path 'dist\InsightClass-Web'
$archive = Get-Item 'InsightClass-Web.zip'

Get-ChildItem $packageDir -Force
Get-ChildItem $packageDir -Recurse -File | Measure-Object Length -Sum

# 不应出现这些开发/其他 GUI 依赖
Get-ChildItem $packageDir -Recurse -File | Where-Object {
  $_.FullName -match 'cefpython|IPython|Sphinx|jupyter|tkinter|PyQt|PySide'
}

Get-FileHash $archive -Algorithm SHA256
```

目录必须包含 EXE、`_internal/`、`_internal/assets/insightclass.ico`、
`_internal/assets/insightclass-tray.png`、`configs/classes.yaml`、空的 `app.yaml`/
`cameras.yaml`、`experiments/`、README 和 LICENSE。检查包内 README 版本与当前
提交一致。

## 8. EXE 冒烟测试

至少验证：

1. 双击无控制台黑框，加载窗口立即出现。
2. EXE 文件属性显示 `1.2.0`；任务栏、标题栏、托盘和前端显示同一品牌图标。
3. `/api/system/status` 返回 200，模型从 loading 到 ready；失败时有明确错误。
4. 首页、CSS、JS、favicon 和品牌 SVG 资源返回 200。
5. 切换浅色/深色主题，检查主界面与 Dashboard 图表，并重启确认偏好保留。
6. 完成图片检测，并检查四类名称和坐标。
7. 测试电脑摄像头启动/停止和设备释放。
8. 测试 RTSP 连接、黑帧回退、停止与重连（有测试设备时）。
9. 关闭窗口后进程留在托盘；托盘可以恢复和退出。
10. 第二次运行 EXE 只唤醒已有窗口，不创建第二个后端。
11. 托盘退出后进程和本地端口均消失。

自动 API 冒烟可读取 `dist/InsightClass-Web/configs/.port` 获取实际端口；不要假设
总是 8000。桌面交互和真实摄像头仍需要人工检查。

## 9. 生成校验文件

```powershell
$hash = Get-FileHash 'InsightClass-Web.zip' -Algorithm SHA256
"$($hash.Hash.ToLower())  InsightClass-Web.zip" |
  Set-Content -Path 'SHA256SUMS.txt' -Encoding ascii
Get-Content SHA256SUMS.txt
```

`SHA256SUMS.txt` 与 ZIP 一起上传 Release。它是发行产物，不提交到仓库时应在发布
后删除或保持忽略。

## 10. 创建 GitHub Release

确认所有文档和代码已经推送，并记录当前 SHA：

```powershell
git status --short --branch
$releaseCommit = git rev-parse HEAD
$remoteCommit = git rev-parse origin-github/main
if ($releaseCommit -ne $remoteCommit) { throw "main 尚未同步到 GitHub" }
```

准备中文发布说明，至少包括新增、修复、安全、运行要求、升级提醒和验证结果。
创建 Release：

```powershell
gh release create v1.2.0 `
  InsightClass-Web.zip `
  SHA256SUMS.txt `
  --repo ygttygtt/InsightClass `
  --target $releaseCommit `
  --title "InsightClass v1.2.0" `
  --notes-file release-notes-v1.2.0.md
```

`gh release create` 会创建标签。不要提前把标签指向未完成提交，也不要复用旧版本
标签发布新代码。

## 11. 远端核验

```powershell
gh release view v1.2.0 --repo ygttygtt/InsightClass
gh release list --repo ygttygtt/InsightClass --limit 10
gh api repos/ygttygtt/InsightClass/releases/tags/v1.2.0 `
  --jq '{tag_name,target_commitish,draft,prerelease,assets:[.assets[]|{name,size}]}'
git ls-remote --tags origin-github refs/tags/v1.2.0
```

确认：

- Release 不是 draft/prerelease（除非发布策略明确要求）
- 标签指向本次已验证提交
- ZIP 与 `SHA256SUMS.txt` 均存在，大小非零
- Release 页面为 latest
- 下载附件重新计算 SHA-256 与校验文件一致

## 12. 升级说明

便携版用户升级时：

1. 从旧目录备份 `configs/app.yaml`、`configs/cameras.yaml` 和 `experiments/`。
2. 将新 ZIP 解压到新目录，不直接覆盖正在运行的旧目录。
3. 退出旧版托盘进程。
4. 将配置/实验按需迁移，首次启动检查默认模型和凭据。
5. 验证后再删除旧目录。

`configs/webview/` 只包含主题偏好和 WebView 缓存，一般不需要迁移；新版本会自动
重建。不要用旧缓存覆盖新发行目录。

`1.1.0` 不再内置 RTSP 密码。旧配置仍可迁移，但公开或共享过的凭据必须轮换。

## 13. 回滚与修订

发现问题时优先发布补丁版本，例如 `v1.2.1`。不要移动已经公开的 `v1.2.0`
标签或静默替换同名附件，否则校验值和下游缓存会失去可信度。

Release 说明错误可以编辑；二进制错误需要撤回问题版本并发布新版本。保留失败
原因和受影响范围，避免只删除记录。

## 14. 常见问题

### WebView 空白

安装 WebView2 Runtime，确认 `_internal/frontend/dist/` 完整，并检查静态资源 API。

### 构建文件被占用

先从托盘退出所有 InsightClass 进程，再重新构建。不要在程序运行期间覆盖 dist。

### 包体异常增大

检查 spec 是否重新导入通用 `webview.platforms`，以及包内是否出现 Qt、CEF、
Jupyter、Sphinx、PyTorch 或 Ultralytics。发行版只使用 Windows winforms 后端和
ONNX Runtime。

### GitHub Release 仍显示旧版

代码推送不会自动更新 Release。必须创建新标签和 Release、上传新 ZIP，并用
`gh release view`/API 核验。README 的 latest 链接只有在新正式 Release 发布后才会
指向新版本。
