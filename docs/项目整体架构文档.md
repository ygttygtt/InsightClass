# InsightClass 整体架构文档

> 版本：`1.1.x`，最后更新：2026-07-21。

## 1. 系统目标

InsightClass 将课堂行为数据闭环和本地视觉分析应用放在同一仓库：

```text
RTSP 录制 -> 视频级划分 -> 抽帧 -> 四类标注 -> Ultralytics 训练
     -> PT 验证 -> ONNX 导出 -> FastAPI 推理 -> React/WebView 展示
```

四个稳定类别为 `phone_use`、`talking`、`sleeping`、`standing`。系统提供检测和
统计线索，不做身份识别，也不替代人工教学判断。

## 2. 技术栈

| 层 | 技术 | 职责 |
|---|---|---|
| 桌面 | pywebview、pystray | Windows 独立窗口、系统托盘、单实例唤醒 |
| 前端 | React 18、TypeScript、Vite | 检测控制、媒体叠加、摄像头管理、Dashboard |
| 图表 | Chart.js、react-chartjs-2 | 分布、摄像头对比和 24 小时趋势 |
| API | FastAPI、Pydantic、uvicorn | REST、MJPEG、上传、配置和静态 SPA |
| 媒体 | OpenCV、Pillow | RTSP、视频帧、图片解码和服务端标注 |
| 推理 | ONNX Runtime | Windows 发行版 CPU 推理 |
| 训练 | Ultralytics | YOLO 训练、验证、PT 推理和 ONNX 导出 |
| 大模型 | urllib OpenAI 兼容客户端 | Chat Completions 连接测试与统计分析 |
| 打包 | PyInstaller | 无控制台 onedir Windows 发行版 |

## 3. 分层与目录

```text
frontend/src/
  App.tsx                 五种检测源、摄像头、设置和媒体叠加
  pages/Dashboard.tsx     实时统计、图表、报表和 AI 分析
  api/client.ts           /api 类型化客户端
  types/index.ts          前后端契约类型

src/insightclass/
  cli.py                  数据、训练、推理和 serve 命令
  schemas.py              核心数据结构
  backends/
    base.py               DetectorBackend 抽象接口
    factory.py            Ultralytics/ONNX 延迟加载工厂
    ultralytics_backend.py 训练、验证和 PT 推理
    onnx_backend.py       ONNX 单帧与视频推理
  data/                   Manifest、抽帧和 YOLO 数据集
  evaluation/             实验记录和汇总
  visualization/          检测结果渲染
  web/
    server.py             唯一 FastAPI 应用
    launcher.pyw          Windows 窗口/托盘/单实例入口
    _server_utils.py      uvicorn 后台线程与就绪轮询
    llm.py                OpenAI 兼容客户端
    model_cache.py        Ultralytics 模型缓存
    schemas.py            Web 检测响应模型
```

依赖方向是 UI/API -> 业务服务 -> 后端/数据 -> 核心结构。模型框架不得反向依赖
Web，前端不得直接读写本地配置文件。

## 4. 运行模式与路径

### 源码模式

- 基础目录：当前工作目录
- 前端资源：`frontend/dist/`
- 模型：`models/`、`experiments/`
- 配置：`configs/`

### PyInstaller 模式

- 可写基础目录：`InsightClass.exe` 所在目录
- 只读资源：`_internal/`（`sys._MEIPASS`）
- 内置前端/模型：`_internal/frontend/dist/`、`_internal/models/onnx/`
- 用户配置：EXE 旁的 `configs/app.yaml`、`configs/cameras.yaml`
- 用户实验：EXE 旁的 `experiments/`

该区分保证升级资源和用户数据不会混在 `_internal/`。发行目录必须整体移动，不能
只复制 EXE。

## 5. 启动与关闭时序

```text
启动 EXE
  -> 读取 configs/.control，尝试唤醒已有实例
  -> 选择空闲 localhost 端口，立即创建加载窗口
  -> 启动控制 socket 和系统托盘
  -> 后台导入 FastAPI/推理模块并启动 uvicorn
  -> API 就绪后加载 http://127.0.0.1:<port>
  -> FastAPI 后台预加载已保存默认模型或内置模型
```

`/api/system/status` 在模型加载期间仍可响应，返回
`idle/loading/ready/error`。窗口关闭事件被转换为隐藏；只有托盘退出会设置
`server.should_exit`、销毁窗口并清理端口文件。

第二个 EXE 通过 localhost 控制 socket 发送 `show`，收到 `ok` 后退出。控制接口
不监听外网，也不接受其他命令。

## 6. 模型生命周期

启动模型选择：

1. `app.yaml` 中已保存且通过路径校验的默认模型
2. 内置 `models/onnx/*.onnx`
3. 用户 `models/onnx/*.onnx`
4. `models/best.pt`
5. 第一个有效实验的 `weights/best.pt`

允许的权重必须是 `.onnx`/`.pt`，真实文件位于 `models/` 或 `experiments/` 内。
ONNX backend 按路径缓存 `InferenceSession`，并通过锁避免并发重复加载；PT 模型由
`model_cache.py` 缓存。设置默认模型会立即启动新的预加载线程。

ONNX 预处理使用 letterbox，后处理恢复源坐标并按类别执行 NMS，避免不同类别之间
互相抑制。

## 7. 摄像头与检测数据流

### RTSP

```text
camera_ip -> 校验已配置摄像头 -> 服务端拼接并转义凭据
          -> RtspStreamRegistry[camera_ip]
          -> 独立 RtspStreamManager 后台线程
          -> 最新 JPEG 帧 -> MJPEG 监看 + /detect/rtsp 推理
```

状态机为 `idle -> connecting -> streaming/error`。读取失败达到阈值后最多重连三次；
初始连续黑帧会从 Channel 101 尝试 102。每台摄像头独立停止，应用关闭时停止全部。

### Webcam

浏览器 `getUserMedia()` 获取视频，前端 Canvas 每秒编码一帧 JPEG，调用
`/api/detect/frame`。停止/切换/卸载组件时终止媒体轨道。

### 图片和视频

图片端点返回带框的 base64 JPEG。视频端点返回原视频尺寸、FPS 和按
`frame_index` 排序的检测结果；前端播放器根据 `currentTime * fps` 二分查找最近
结果并在 Canvas 上换算坐标。

### 批量任务

上传阶段创建随机临时目录和 pending job。启动时在锁内将状态原子切换为
processing，拒绝重复启动。后台线程顺序处理文件，单项异常记录为 error；约一小时
后或应用退出时删除任务和临时目录。

## 8. Dashboard 与大模型

`DashboardStats` 使用锁保护：

- 每摄像头四类累计计数与最后更新时间
- 每摄像头最近 24 小时的小时桶
- 当前摄像头在线状态（30 秒 TCP 探测 + 活跃流状态）

数据只存在内存中，重启清空。`/api/dashboard/history` 返回
`simulated: false`。

大模型配置优先级：环境变量 > `app.yaml` > 默认 Base URL。客户端规范化 Base
URL，调用 `<base_url>/chat/completions`，可选 Bearer Key，并验证 choices/message
响应。Dashboard 只发送统计 JSON，不发送视频帧。

## 10. 输入边界

| 输入 | 限制 |
|---|---|
| 图片 | 25 MiB，5000 万解码像素；JPG/JPEG/PNG/BMP/WebP |
| 单视频 | 2 GiB；MP4/AVI/MOV/MKV/M4V/WebM |
| 批视频 | 最多 20 个，总计 8 GiB；仍受单文件限制 |
| 摄像头 CSV | 5 MiB，仅 `.csv` |
| 大模型 prompt | 4000 字符 |
| 大模型 context JSON | 20000 字符 |
| 大模型超时 | 1..300 秒 |

上传采用分块读取/写入，超限时立即拒绝并清理临时文件。文件扩展名校验不能替代
解码校验，两者都执行。

## 11. 配置格式

`configs/classes.yaml`：受版本控制的稳定类别表。

`configs/cameras.yaml`：

```yaml
cameras:
  - ip: 192.0.2.10
    name: 教室 A
    group: custom
    note: 前视角
```

摄像头记录不保存独立密码，统一使用 `app.yaml` 中的共享凭据。

`configs/app.yaml`（本地、不可提交）：

```yaml
default_model: <managed-by-application>
rtsp_credentials:
  username: admin
  password: <local-secret>
  port: 554
llm:
  base_url: https://api.openai.com/v1
  model: <model-name>
  api_key: <local-secret>
  timeout: 60
```

GET 设置接口不会返回 `<local-secret>`，只返回 `has_*` 和尾部掩码。

## 12. 安全边界

- 摄像头只接受 IPv4，且必须先存在于用户摄像头配置。
- RTSP 用户名/密码使用 URL 转义，日志不输出完整 URL。
- 大模型 Base URL 只允许 HTTP(S)，禁止 URL 内嵌凭据。
- 模型和实验文件通过 `resolve()` 限制在允许根目录。
- 桌面 API 只监听 localhost；CLI 暴露局域网时部署者负责认证和 TLS。
- CORS 只允许本地 Vite 开发源；发行前端使用同源访问。
- 运行时密钥、内部 IP、数据集和课堂媒体均由 `.gitignore`/发行流程排除。

项目当前没有用户认证和数据库。不能将 `0.0.0.0` 的裸服务直接暴露到不可信网络。

## 13. 构建与验证

`InsightClass.spec` 将前端、类别表和 `models/onnx/*.onnx` 打入 `_internal/`，入口为
`launcher.pyw`，`console=False`。spec 排除 PyTorch、Ultralytics、Qt、CEF、
Jupyter、Sphinx、tkinter 等非发行依赖。

发布前执行：

```powershell
python -m pytest -q
ruff check src scripts tests
Push-Location frontend
npm audit --omit=dev --audit-level=high
npm run build
Pop-Location
.\scripts\build_package.ps1 -SkipDeps
```

自动化测试覆盖 ONNX 前后处理、上传边界、路径安全、RTSP 配置/流、批任务、模型
生命周期、桌面激活和大模型契约。打包后仍需真实 EXE 冒烟，因为 WebView2、托盘、
PyInstaller 隐式导入和原生 DLL 无法只靠单元测试验证。
